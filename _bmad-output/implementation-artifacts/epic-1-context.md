# Epic 1 Context: Foundation — Log in to a Secure, Auditable Persona Workspace

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Stand up a running, locally deployable Fine (Spring Boot 4.1 modular monolith + Angular 22 SPA, Docker Compose) on which every later feature lands safely. Study participants, the advisor and the researcher can log in to their own surface; persona data is isolated server-side; module boundaries and domain purity are enforced by tests; the simulated clock, fingerprinted agent configuration, the single LLM port and an append-only audit trail exist before any feature is built. This matters because the thesis claims auditability and determinism, and those guarantees must be structural from day one.

## Stories

- Story 1.1: Project scaffold with enforced architecture guardrails
- Story 1.2: One image, one compose file — Fine runs locally
- Story 1.3: Log in as a persona, an advisor or a researcher
- Story 1.4: Simulated clock, request context and versioned agent configuration
- Story 1.5: Append-only audit trail and evidence store
- Story 1.6: LLM behind one port, served by a pinned Ollama model
- Story 1.7: Persona reset for reproducible sessions

## Requirements & Constraints

- Only Synthetic Personas; persona isolation is enforced on the server, never trusted from the client.
- Roles `PERSONA`, `ADVISOR`, `RESEARCHER`. No advisor UI and no research UI: those roles use Swagger UI and scripts. Research endpoints exist only under the Spring profile `research` (otherwise 404).
- Behaviour is switched only by versioned configuration files with a fingerprint recorded in audit; no other feature flags. Experiment results (E1–E4) enter only as config files carrying a `derivedFrom` block; no experiment tooling is built.
- Every released response, Notification, Action and extraction has an append-only Audit Record written in the same transaction; audit failure means nothing is released.
- Identical inputs yield identical outputs; domain time comes only from the persona's simulated clock.
- Tables are created by the story that first needs them (one Flyway migration per story). Every story adding persona-owned state registers it with persona reset.
- UI, code, prompts and docs in English. Desktop only (≥ 1280 px), light theme only, WCAG 2.2 AA floor.

## Technical Decisions

- **Modules:** `de.financetool.{shared, personas, bank, knowledge, audit, llm, profile, documents, core, actions, escalation, advisory, monitoring, research}`, layers `domain | application | port | adapter | web`. A module's API is its base package only; sub-packages are internal. Allowed dependencies (verified by `ApplicationModules.verify()`): all → `shared`; `documents` → llm, audit, personas; `core` → bank, knowledge, audit, documents; `actions` → core, bank, profile, audit; `escalation` → audit; `advisory` → core, profile, knowledge, llm, audit, escalation, personas; `monitoring` → core, actions, profile, escalation, audit, personas, documents; `research` → advisory, monitoring, actions, escalation, profile, bank, knowledge, personas, audit, documents.
- **Purity:** `..domain..` uses only `java.*` and other domain classes (no Spring/Jakarta/JPA/Jackson). No `LocalDate.now()`, `Instant.now()`, `Clock.systemDefaultZone()` in domain or application (ArchUnit).
- **Transactions:** `*UseCase` classes are the only `@Transactional(REQUIRED)` entry points; writing module services are `MANDATORY`. Only synchronous `@EventListener` may break cycles; no `@ApplicationModuleListener`, `@Async`, `@TransactionalEventListener`.
- **RequestContext** `(agentConfig, configFingerprint, thresholds, kbSnapshot, seeds, asOf, personaId, runId)` is an immutable record in `shared`, built by the use case and passed explicitly.
- **API:** REST JSON under `/api`; errors RFC 9457 `ProblemDetail` with a closed `code` enum. Springdoc OpenAPI with explicit `Money` (decimal string + currency), `ProblemCode` and sealed-type discriminators; Angular client generated by `ng-openapi-gen` (`services: true, promises: false`), regenerated in the build and diff-checked; no hand-written DTOs, no client-side financial maths, polling instead of streaming.
- **Security:** Spring Security 7 session login, `POST /api/auth/login` JSON 200/401 without redirect, `csrf(c -> c.spa())`, persona id only from the principal, `PersonaScope` on persona-scoped repositories.
- **Config:** `config/agent/<id>.yaml` selected by `APP_AGENT_CONFIG`, bound via `@ConfigurationProperties` + Jakarta Validation; `config/`, `data/`, `models/` read from `APP_HOME`; `.gitattributes` forces LF there. `ConfigFingerprint` = SHA-256 over LF-normalised bytes of the AD-25 files plus `config/documents.yaml`, `config/letters/`, `data/rules`, in sorted path order.
- **Audit:** `audit_records`, `evidence_items` with triggers rejecting UPDATE/DELETE/TRUNCATE; app connects as non-owner (INSERT/SELECT only); Flyway migrates as owner; payload serialised only by `AuditPayloadMapper`; JSONL export.
- **LLM:** `llm.LlmPort.generate(role, messages, decoding, schema)` → `LlmResult(text, modelTag, digest, decoding, promptTokens, truncated, latency)`; thin Ollama `/api/chat` + `/api/embed` client on `RestClient`, no Spring AI; `models/lock.json` checked fail-fast at startup.
- **Conventions:** Money `BigDecimal` scale 2 HALF_UP, `NUMERIC(14,2)`; fractions in the domain; `LocalDate` for domain dates, `Instant` UTC for technical timestamps; Flyway only, no `ddl-auto`; JSON logs to stdout; records and sealed interfaces for domain types; persona ids `p-<name>`, entity ids UUID.
- **Stack:** Java 25, Spring Boot 4.1.1, Spring Modulith 2.1.1, springdoc 3.1.1, ArchUnit `archunit-junit6` 1.5.1, JUnit 6, Testcontainers 2.0.x, Maven wrapper; Node 24.15+, Angular 22.2, TypeScript 6.0, ng-openapi-gen 1.1.x. Runtime images `pgvector/pgvector:0.8.2-pg17`, `ollama/ollama:0.40.6`.
- **Deployment:** one multi-stage image (Angular build inside Spring Boot static resources) and one `deploy/docker-compose.yml` (`app`, `db`, `ollama` with `OLLAMA_KEEP_ALIVE=-1`); environments differ only in env vars. Azure deferred.

## UX & Interaction Patterns

- Atruvia brand layer on Angular Material M3: navy text/structure, action-blue primary, ice/light-cyan surfaces, Inter with tabular figures, 44 px pill buttons, 20 px rounded cards, flat elevation, light theme only.
- Navy 64 px app header: "Atruvia" text wordmark, divider, "Fine", simulated-date chip "Today: …" (research profile only), logged-in name, Log out.
- Workspace shell: Overview left (tabs Home, Liquidity, Wealth & Retirement, Letters; active tab in `?tab=`), Chat right (440 px; 500 px from 1440 px).
- Login copy: wrong credentials → "That username and password don't match."; session expiry → redirect with "You were logged out after a while of inactivity. Please log in again." Document language `en`.

## Cross-Story Dependencies

- 1.1 is the base for all stories; 1.2 packages it; 1.3 adds the first tables (`personas`, `users`, `persona_state`); 1.4 needs `persona_state` from 1.3; 1.5 needs `RequestContext` from 1.4; 1.6 needs `AgentConfiguration` from 1.4; 1.7 needs 1.3–1.5.
- Safety-critical: 1.3 (persona isolation) requires a code review after build.
- Later epics depend on Epic 1's guardrails (module graph, purity, use-case transactions, audit, config fingerprint).
