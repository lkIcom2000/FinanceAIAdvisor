Cache reads dominate: about 130M tokens across the epic, roughly 20× the reviewer subagents (0.2–1.4M each). At cache-read pricing (a tenth of input) they still outweigh output tokens by a wide margin. Cache read ≈ API calls × context size, so the levers are **fewer calls** and **a smaller context**:

| # | Lesson | Evidence |
|---|---|---|
| L1 | **Too many single-step calls.** 6.2 made 152 calls with 76 Edits; most edits and reads went out one per message. Independent reads, greps and edits on different files in one message cost one call instead of many. At ~200k context, each saved call saves ~200k cache-read tokens. | session 7f726662: 152 calls, avg context ≈ 207k |
| L2 | **Whole-file reads stay in context for the rest of the session.** The largest tool results were full `cat`/`Read`s of big files: `TurnOrchestrator` (31.7k chars, read in full in 7.1), a persisted oversized tool output read back in full in 6.2 (31.7k), `CheckChain` (27.9k), `sed -n 140,564p` (26.4k), `ToolPlan`, `MonteCarloProjection`, an architecture shard (~23k each). One 30k-char read carried through 100 later calls is ~0.75M cache-read tokens. Use `grep -n` + `sed` windows of ≤ 80 lines. | sessions 7f726662, 918f9cf6, dcb9864a, d468d8c4 `biggest` |
| L3 | **Failed build rounds.** 6.1 had 8 of 12 Maven runs fail (2 compile), 6.4 had 4 of 11 (2 compile). Each failure adds a read-fix-rerun loop at full context. The 6.1/6.2 memory rules (grep tests for changed texts, `clean test-compile` after signature changes) cut it to 1 of 8 in 7.1. Keep them. | mvn counts above |
| L4 | **Fresh-session live checks are cheap.** Live checks in their own session cost 4–7M cache reads, against 21–31M for the story sessions, because they start without the implementation context. Running every live check this way should be the rule. | sessions 7d79e152, 98753115 |
| L5 | **Session-start overhead repeats.** Every session `cat`s `build-loop-economy.md` (~9k chars, growing with each rule) although `MEMORY.md` and the handoff checklist already carry the rules; the retro skill's references add 25k chars. Trim the memory file to the rules in force and stop re-reading it. | `biggest` in 7d79e152, 98753115, 73dec930 |
| L6 | **Live checks keep producing grounding patches.** Two of five stories needed NLU grounding rules after the live check, and both rules needed tightening later (F4). One combined live check per epic block (as in 6.4 + 7.1) halves the ~55 s restarts and the per-session setup. | specs 6.3/6.4, `9cd9de8` |
| L7 | **Plans got lost between sessions.** "Before Epic 7" for Story 13.2 lived only in `epics.md` and `sprint-status.yaml`, not in the handoff note each session starts from (F5). Handoff notes must carry scheduled prerequisites. | `epic-6-handoff.md` (no mention of 13.2) |

What worked: one story per session with `/clear` kept contexts at ~150–200k instead of growing across stories; one combined sonnet reviewer per story (~0.2–0.7M cache reads) caught 6–8 real issues each at a small share of the main session's cost; the epic-end batch review found two medium issues no single story review saw.
